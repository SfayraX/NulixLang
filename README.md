# Nulix

Один язык на весь стек — от приложений до ядра ОС и голого железа. Программа описывает, что сделать, а Nulix решает, как выполнить это на конкретной машине, и специализирует программу под её возможности как можно позже.

## Состояние

Проект перезапущен 14 ноября 2026 года: язык перепроектирован, реализация начинается с нуля. Компилятор начат: готовы лексер и разборщик. В репозитории лежат спецификация, формальная грамматика, описание ядра IR и начало компилятора на Rust.

Прежний прототип v0.2 удалён из дерева и остаётся в истории git.

## Спецификация

[spec/nulix.md](spec/nulix.md) — спецификация языка: принятые решения и открытые вопросы; у каждого пункта постоянный номер вида 9.14. [spec/rationale.md](spec/rationale.md) — обоснования решений с источниками. Это главная копия спецификации: правки идут через pull request и действуют после слияния. До 20 ноября 2026 главной копией был рабочий документ, а эти файлы — его выгрузкой; последняя выгрузка — ревизия 279.

## Грамматика

- [spec/grammar.md](spec/grammar.md) — лексика, приоритеты и полный текст правил; принято 15 ноября 2026.
- [grammar/nulix.lark](grammar/nulix.lark) — те же правила в виде, который читает проверка.
- Проверка: `pip install lark`, затем `python3 tools/grammar/check.py grammar`. Она собирает грамматику как LALR(1) в строгом режиме, где любой конфликт — ошибка, и разбирает примеры из папки `grammar`. Каждый фрагмент в обратных кавычках из `spec/nulix.md`, кроме одиночных лексем, обязан быть учтён в `grammar/fragments.tsv` — разобран или пропущен с причиной; список всех фрагментов с номерами пунктов — `grammar/spans.tsv`, после правки спецификации он пересобирается командой `python3 tools/grammar/spans.py spec/nulix.md grammar/spans.tsv`. Источник истины — `grammar/nulix.lark`. Проверка написана на Python и остаётся после появления разборщика на Rust: только она доказывает отсутствие конфликтов, а разборщик обязан с ней совпадать.
- Документ пересобирается командой `python3 tools/grammar/build_doc.py grammar spec/grammar.md`.

## Ядро IR

[spec/ir-core.md](spec/ir-core.md) — устройство переносимого Nulix IR: решения, текстовая форма, примеры и порядок реализации. Принято 16 ноября 2026. Текстовую форму проверяет тест `compiler/tests/ir_text.rs`, смысл инструкций — тест интерпретатора `compiler/tests/interp.rs`, правила проверки — тест проверщика `compiler/tests/verify.rs`.

## Проверка явного ядра

[spec/core-check.md](spec/core-check.md) — что компилятор проверяет в исходнике на шаге 2, до перевода в IR: подмножество языка, имена, типы, владение и режимы, полнота `match`, устройство проверки и порядок работ. Принято 22 ноября 2026.

## Компилятор

- `compiler/` — начальный компилятор на Rust. Пока в нём лексер и разборщик: текст программы превращается в синтаксическое дерево (`compiler/src/ast.rs`). Проверок смысла ещё нет. Идёт шаг 2: готовы данные IR (`compiler/src/ir.rs`), их текстовая форма (`compiler/src/ir_text.rs`), интерпретатор IR (`compiler/src/interp.rs`) и проверщик IR (`compiler/src/verify.rs`).
- Тесты: `cd compiler && cargo test`. Они сверяют лексер и разборщик с проверочными — лексером на Python и разборщиком Lark по `grammar/nulix.lark`. На каждом тексте обе стороны обязаны одинаково принять его или отвергнуть и построить одинаковое дерево. Сверка идёт по четырём файлам в папке `grammar`:
  - `tokens.golden.tsv` — лексемы всех примеров;
  - `trees.golden.tsv` — деревья примеров из спецификации, отрицательных примеров и тестовых программ;
  - `fuzz.golden.tsv` — 3000 текстов, выведенных из правил грамматики: по одному на каждое раскрытие каждого правила, случайные и они же с одной порчей;
  - `depth.golden.tsv` — тексты у предела вложенности: на 255, 256 и 257 уровнях для каждого способа вложить одно в другое.
- Эталоны пересобираются командами:
  - `python3 tools/grammar/dump_tokens.py grammar > grammar/tokens.golden.tsv`
  - `python3 tools/grammar/dump_trees.py grammar > grammar/trees.golden.tsv`
  - `python3 tools/grammar/fuzz.py grammar 3000 1 --max-tokens 150 > grammar/fuzz.golden.tsv`
  - `python3 tools/grammar/depth_cases.py grammar > grammar/depth.golden.tsv`
- Интерпретатор IR проверяет `tests/interp.rs`: целая арифметика сверяется с проверяющими операциями Rust, преобразования — с независимыми расчётами, а программы на IR из `tests/ir/` — с ожидаемыми результатами, авариями и остановками на неверном IR.
- Проверщик IR проверяет `tests/verify.rs`: правильные программы из `tests/ir/` и пример из `spec/ir-core.md` принимаются, а принятое исполняется без «неверного IR»; неверный IR отвергается с ожидаемым сообщением; каждая порча правильного IR одной отметкой или инструкцией, гарантированно делающая его неверным, отвергается. Тесты из внешней оценки проверщика: `tests/verifier_adversarial.rs` — точечные программы с ожидаемыми вердиктами, `tests/verifier_typing.rs` — сверка типизации с интерпретатором, `tests/verifier_fuzz.rs` — фаззер; полный прогон фаззера — `FUZZ_N=150000 FUZZ_SEED=7 cargo test --release --test verifier_fuzz`. Скрипты в `tools/verifier/` ослабляют проверки проверщика по одной и меряют его пределы.
- Текстовую форму IR проверяет `tests/ir_text.rs`: канонические тексты и примеры из `spec/ir-core.md` записываются обратно буква в букву, 2000 случайных модулей переживают запись и чтение без изменений, каждый из них с одной порчей не обрушивает чтение, неверный текст отвергается с номером строки.
- Большой прогон в репозиторий не кладётся. Его собирает `python3 tools/grammar/fuzz.py grammar 200000 3 --exhaustive > /tmp/big.tsv`, а сверяет `cd compiler && NULIX_EXTRA_TREES=/tmp/big.tsv cargo test --release --test parser_golden`.
- Посмотреть лексемы или дерево файла: `cd compiler && cargo run -- lex ../grammar/samples/03-скрипт.nx` и `cargo run -- parse ../grammar/samples/03-скрипт.nx`.
- Предел вложенности — 256 уровней: текст глубже отвергается с ошибкой, а не обрушивает разборщик. Что считается уровнем, записано в `spec/grammar.md`, раздел 3. Цепочки вроде `a + b + c` и `else if` в дереве хранятся списками и вложенностью не считаются. На 256 уровнях отладочной сборке нужно до 9,3 МБ стека, поэтому компилятор работает на потоке со стеком 64 МБ (`compiler/src/stack.rs`).
- Чего разборщик пока не делает: останавливается на первой ошибке; не сверяет метки `end` с именами.
- Правила кода: без `unsafe`, без собственных макросов и без внешних зависимостей, чтобы перенос на Nulix был почти построчным.
- Нужен Rust 1.87 или новее: это записано в `compiler/Cargo.toml`, и Cargo со старой версией сразу откажется. Работа идёт на Rust 1.97.0.
- Проверки на GitHub (`.github/workflows/ci.yml`) идут при каждом pull request и при изменении `main`: формат и `clippy` без предупреждений на Rust 1.97.0; тесты на Rust 1.87 и на последнем стабильном; проверка грамматики; пересборка эталонов, списка фрагментов спецификации и `spec/grammar.md` — они обязаны совпасть с лежащими в репозитории; проверка номеров пунктов спецификации.
